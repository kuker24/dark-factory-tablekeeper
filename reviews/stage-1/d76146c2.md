## Findings (REJECT)

### Finding 1 — wrong JSON type on `table_id`/`restaurant_id` returns 422, must be 400

Req 11 / spec §5: `malformed_request` (400) is required for "a field of the wrong JSON
type". The only wrong-type carve-outs are `party_size` and bare-`starts_at_local` (D3).
`restaurant_id`/`table_id` are "other wrong JSON types" and must be 400.

Observed (clean state, deterministic):

- `POST /reservations` with `"restaurant_id": 17` → `422 validation_failed`
- `POST /reservations` with `"table_id": 17` (also `null`, `true`) → `422 validation_failed`
- `PATCH /reservations/{ref}` with `"table_id": 17` → `422 validation_failed`
- `POST /reservation-moves` with entry `"table_id": 17` → `422 validation_failed`

Contrast (all correct): `starts_at_local` non-string → 400; `email`/`password`/
`display_name` non-string → 400; `party_size` non-integer → 422.

Root cause: `stage-1/validation.py` `check_id()` raises `ValidationFailed` (422) for any
non-valid value including non-strings; it does not distinguish wrong JSON type (400) from
invalid value/format (422). Used for request fields at `operations.py:500,501,657,758`.
Not covered by the shipped checks (only malformed JSON is tested).

### Finding 2 — idempotency identity ignores the request path

Req 29 / spec §7: "A replay means the same user sending the same method, the same **path**
and the same body. The same key with the same body on a different path is a different
request, not a replay, and must succeed normally." Reuse/`409` is likewise relative to the
same request identity.

Observed (clean state, one user, one key):

1. `POST /reservations` (key `K`, body `B`) → `201`.
2. `POST /reservation-moves` (same key `K`, same body `B`) → `200` **replaying the
   `/reservations` response** instead of executing/succeeding as a new request.
3. With a different body on the moved path: `409 idempotency_key_reuse`.

Root cause: `operations.py:_idempotency_lookup` / `_idempotency_store` key receipts on
`(user_id, key)` only and compare `rec["body"] != body`; the path is neither stored nor
part of the identity. Not covered by the shipped checks.
